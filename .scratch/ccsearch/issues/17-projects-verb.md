# `projects`: list the Projects in the Store

Status: ready-for-agent
Category: enhancement

## Why

Sibling to `sessions` (issue 16) under the unit-listing verb model (ADR 0004): enumerate the Projects in the Store so you can see what history exists and what substring to pass to `--project`. Lower-value than `sessions` (you usually know your own project names), but the natural completion of the listing pair — most useful to `--all` users exploring across projects.

> **RESOLVED 2026-06-02 via grill-with-docs.** Identity = on-disk directory (not real cwd); case-fold grouping for cross-OS consistency; display the newest Session's real `cwd` with the encoded name as fallback; row = name + Session count + last-touched. Recorded in **ADR 0005**. The original open question and its analysis are kept below for context; the authoritative spec is the Agent Brief at the bottom.

## The open sub-design (resolved — see ADR 0005)

ADR 0001: a single **logical Project can map to several directories** under `~/.claude/projects/` — drive-letter case wobble on Windows (`E--…` vs `e--…`) and the lossy non-alphanumeric→`-` encoding (`a\b\c`, `a-b-c`, `a.b.c` all collapse). `--project` already handles this by searching the **union** of matching directories. A naive `projects` listing would **double-count** the same logical Project as two rows.

So the core decision to resolve at triage:

1. **List directories raw** — one row per `~/.claude/projects/` subdirectory. Honest about what's on disk, but shows duplicates the rest of the tool deliberately unions away. Inconsistent with `--project`.
2. **List de-duplicated logical Projects** — collapse case-variant / encoding-collision directories into one row (the same union rule `--project` uses). Consistent with how the tool already treats a Project, but needs a canonical display name and a defined merge of their metadata (counts, last-touched).
3. Something else surfaced at triage.

Leaning option 2 (consistency with ADR 0001's union), but it forces sub-questions: what is the **display name** of a logical Project (the encoded directory string? a real `cwd` read out of a Record, per ADR 0001's "read the cwd field"?), and when two directories merge, how do their **last-touched dates / session counts** combine?

## Likely shape (to firm up at triage)

- `ccsearch projects` lists Projects, newest-touched first, reusing as much of the `sessions`/`search` scope and recency machinery as fits.
- Each row likely: a Project display name + session count + last-touched date. (Row format is a triage decision — unlike `sessions`, there is no existing header to reuse verbatim.)
- `--since` should compose (Projects touched since X). `--all` is implicit (the whole Store); `--project <substr>` could filter the listing.

## Out of scope

- Verb naming / the action-vs-noun-verb question — already decided in ADR 0004.
- Anything about `sessions` (issue 16).

## Blocked by

- 16-sessions-verb (shares scope/recency plumbing; build `sessions` first)

## Comments

### 2026-06-02 — Triage decision

> *This was generated by AI during triage.*

Grilled the design (`/grill-with-docs`). Key reframings from exploring the code and the real Store:

- The "double-counting landmine" is much smaller than the draft implied. Two directories for one logical Project can only exist on a **case-sensitive** Store (Linux/WSL); on Windows/macOS the filesystem makes `E--foo` and `e--foo` the same directory. The maintainer's Store has 12 directories, zero case-collisions.
- **Lossy-encoding collisions are not a lister's problem** — they already collapse to one directory on disk, and reverse-decoding is impossible (ADR 0001).
- **Records carry the real `cwd`**, so the display can show the true path instead of the encoded name.

Decisions (authoritative spec in the Agent Brief): identity = on-disk directory; **case-fold grouping** so behaviour is identical on every OS (merge directories whose names are case-insensitively equal — ADR 0001's union rule without a cwd); display the newest Session's real `cwd`, falling back to the encoded name; row = `name · N sessions · last-touched`; sort recency-desc; `--since` and `--project` compose; `--all`/`-l` not defined. The directory-vs-cwd identity choice is recorded in **ADR 0005**.

### 2026-06-02 — Agent Brief

## Agent Brief

**Category:** enhancement

**Summary:** Add a `projects` verb that lists the Projects in the Store, one row per on-disk directory, folding case-variant directories together so the listing is identical on every OS. Each row shows the Project's real path (read from a Record), its Session count, and when it was last touched, newest first.

**Current behavior:**
`ccsearch` has three verbs: `search`, `show`, and `sessions` (ADR 0002, ADR 0004). All scope by **directory** (ADR 0001): `find_project_dirs` forward-encodes a cwd and matches directory names case-insensitively; `--project <substr>` filters directory names; `sessions` lists Sessions within a scope. There is no way to enumerate the Projects themselves — to see what history exists, or what substring to pass to `--project`.

**Desired behavior:**
- `ccsearch projects` lists the Projects in the Store, **one row per on-disk directory**, newest-touched first. There is no Query.
- **Identity is the directory, not the real cwd** (ADR 0005). Directories whose names are equal case-insensitively are **folded into one row** (ADR 0001's union rule applied without a cwd), so the same logical Project never appears twice on a case-sensitive Store and the verb behaves the same on Windows/macOS/Linux/WSL. On a case-insensitive Store this grouping is a no-op (each directory is its own group).
- Each row is `name · N sessions · last-touched`:
  - **name** — the real `cwd` read from the group's **newest** Session (e.g. `E:\projects\rust\claude-code-conversation-search`), falling back to the encoded directory name when no Session in the group carries a `cwd`.
  - **N sessions** — the count of Sessions the `sessions` verb would list for the group (sum across merged directories).
  - **last-touched** — the newest Session `timestamp` in the group, rendered as its date prefix (the same recency key search/`sessions` use); omitted if the group has no dateable Session.
- **Sorted recency-descending** by last-touched (newest first); groups with no timestamp sort last; ties broken by the (lowercased) group name for determinism.
- A directory (group) with **no listable Sessions is omitted** — an empty Project has nothing to reopen (this is the one content-ish filter; it drops only genuinely empty directories, not Sessions).
- `--since <when>` composes (only Projects whose last-touched is at/after the cutoff; undateable groups excluded, per the existing `timestamp_is_since` rule).
- `--project <substr>` filters the listing to groups whose directory name contains the substring (same case-insensitive match `search` uses).
- `--all` and `-l` are **not defined** for `projects` (it is inherently whole-Store; nothing consumes a Project path) — clap rejects them.
- Empty Store (or none after `--since`) prints `No projects.\n` and **exits 0**.
- Output is plain text (no ANSI), consistent with `sessions`.

**Key interfaces (by contract, not location):**
- A new `projects` subcommand with a `ProjectsArgs` defining only `--since` and `--project`. Mirror `SessionsArgs`. The search-only flags it omits are rejected by clap for free.
- Reuse `project_dir_paths(projects_root)` to enumerate directories, and `enumerate_sessions` / the per-Session metadata pass (`session_info` or its internals) to get each Session's `timestamp` and `cwd`. Add a `ProjectInfo` (name/display-path, session_count, last_touched) and a `list_projects(projects_root) -> Vec<ProjectInfo>` that groups by lowercased directory name, sums counts, maxes timestamps, and picks the newest Session's `cwd` for the display name. Sort with the same comparator shape as `list_sessions` (`b.last_touched.cmp(&a.last_touched).then_with(|| a.name.cmp(&b.name))`).
- The `cwd` lives in Records as a top-level `"cwd"` string (alongside `timestamp`); read it in the same per-line pass that finds the newest timestamp. The display `cwd` must come from the **newest** Session in the group (track timestamp+cwd together), not just any Session.
- `format_projects(&[ProjectInfo]) -> String` renders `name · N sessions · date` per row with the `No projects.` empty case; mirror `format_sessions`. Reuse `date_prefix` for the date.
- Reuse `since_cutoff` / `timestamp_is_since` and the shared `parse_since` / `build_scope` helpers where they fit (note `projects` is always whole-Store, so it does not need `build_scope`).

**Acceptance criteria:**
- [ ] `ccsearch projects` lists one row per Project in the Store, newest-touched first, as `name · N sessions · date` (CLI test against a fixture Store with two Projects of different ages).
- [ ] The row name is the real `cwd` from the newest Session (assert a known path appears); a Project whose Sessions carry no `cwd` falls back to the encoded directory name.
- [ ] The Session count equals the number of Sessions `ccsearch sessions --project <that>` would list for the Project.
- [ ] Two directories whose names differ only by case (e.g. `E--proj-x` and `e--proj-x`) are folded into **one** row whose count is the sum and whose last-touched is the newer of the two (unit test on `list_projects`; this is the cross-OS guarantee).
- [ ] `--since` excludes a Project whose newest Session predates the cutoff; `--project <substr>` filters to matching Projects.
- [ ] `--all` and `-l` are rejected (clap error, non-zero exit).
- [ ] A directory with no listable Sessions does not appear; empty Store prints `No projects.` and exits 0; piped output carries no ANSI.
- [ ] `cargo test` green and `cargo clippy --all-targets -- -D warnings` clean.

**Out of scope:**
- Identity by real `cwd` (grouping/splitting Sessions by recorded path) — rejected in ADR 0005; identity is the directory.
- Un-merging lossy-encoding collisions (one directory holding multiple real paths stays one row).
- `-l` / piping and an `--all` flag — no consumer / meaningless for a whole-Store verb.
- Any new domain term — `projects` enumerates the existing **Project**; CONTEXT.md's Project entry was only sharpened to note the multi-directory case (done during triage).
